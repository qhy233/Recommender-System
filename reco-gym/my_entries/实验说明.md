# RecoGym 强化学习推荐系统实验指南

## 一、项目概述

### 1.1 RecoGym简介

RecoGym是RecSys 2018 REVEAL workshop论文配套的推荐系统强化学习实验环境，采用OpenAI Gym风格设计，专门用于研究和验证推荐系统中的强化学习算法。

**核心特点：**

- 模拟真实电商用户行为模式
- 支持离线训练与在线学习
- 提供多种基线Agent实现
- 支持自定义Agent开发

### 1.2 实验目标

本实验通过实现多种不同类型的推荐Agent，逐步理解强化学习在推荐系统中的应用，并在V5版本中继续尝试算法增强与状态增强：

| Agent类型             | 理论基础                    | 学习目标                  |
| --------------------- | --------------------------- | ------------------------- |
| Popularity Agent      | 协同过滤、群体智慧          | 理解基于统计的推荐方法    |
| ε-greedy Agent       | 探索-利用困境               | 掌握探索策略的设计        |
| Policy Gradient Agent | REINFORCE算法               | 理解策略梯度方法          |
| DQN Agent             | Q-learning                  | 掌握价值函数方法          |
| Actor-Critic Agent    | TD + Policy Gradient        | 理解Actor与Critic协同更新 |
| PPO Agent             | Clipped Policy Optimization | 理解稳定策略更新的思路    |

### 4.2 实验1：Popularity Agent

**核心思想：** 统计每个物品被用户浏览的次数，推荐浏览次数最多的物品。

```python
class PopularityAgent(Agent):
    def __init__(self, config):
        super(PopularityAgent, self).__init__(config)
        self.product_views = np.zeros(config.num_products)
  
    def train(self, observation, action, reward, done=False):
        if observation is not None:
            for session in observation.sessions():
                self.product_views[session['v']] += 1
  
    def act(self, observation, reward, done):
        if np.sum(self.product_views) == 0:
            action = np.random.randint(self.config.num_products)
        else:
            action = np.argmax(self.product_views)
    
        return {
            't': observation.context().time(),
            'u': observation.context().user(),
            'a': action,
            'ps': 1.0,
            'ps-a': np.zeros(self.config.num_products)
        }
```

**理论对应：**

- ItemCF中的物品流行度
- 协同过滤的群体智慧思想
- 简单但有效的基线方法

### 4.3 实验2：ε-greedy Agent

**核心思想：** 以概率ε随机探索，以概率1-ε利用当前最优。

```python
class EpsilonGreedyAgent(Agent):
    def __init__(self, config, epsilon=0.1):
        super(EpsilonGreedyAgent, self).__init__(config)
        self.epsilon = epsilon
        self.product_clicks = np.zeros(config.num_products)
        self.product_recommendations = np.zeros(config.num_products)
  
    def train(self, observation, action, reward, done=False):
        if action is not None:
            self.product_recommendations[action['a']] += 1
            self.product_clicks[action['a']] += reward
  
    def act(self, observation, reward, done):
        if np.random.random() < self.epsilon:
            # 探索：随机选择
            action = np.random.randint(self.config.num_products)
        else:
            # 利用：选择点击率最高的物品
            click_rates = np.divide(
                self.product_clicks, 
                self.product_recommendations,
                out=np.zeros(self.config.num_products),
                where=self.product_recommendations != 0
            )
            action = np.argmax(click_rates)
    
        return {
            't': observation.context().time(),
            'u': observation.context().user(),
            'a': action,
            'ps': self.epsilon / self.config.num_products if np.random.random() < self.epsilon else 1 - self.epsilon + self.epsilon / self.config.num_products,
            'ps-a': np.zeros(self.config.num_products)
        }
```

**理论对应：**

- 强化学习中的探索-利用困境
- Multi-Armed Bandit问题的经典解法
- ε值需要根据场景调优

### 4.4 实验3：Policy Gradient Agent (REINFORCE)

**核心思想：** 直接学习推荐策略π(a|s)，使用策略梯度更新参数。

**策略梯度公式：**

$$
\nabla J(\theta) = \mathbb{E}[\nabla \log \pi(a|s) \cdot R]
$$

```python
class PolicyGradientAgent(Agent):
    def __init__(self, config, learning_rate=0.1):
        super(PolicyGradientAgent, self).__init__(config)
        self.lr = learning_rate
        self.num_products = config.num_products
        self.theta = np.zeros(self.num_products)
        self.trajectory = []
        self.temperature = 2.0
  
    def get_policy(self):
        # Softmax策略
        exp_theta = np.exp(self.theta / self.temperature)
        return exp_theta / np.sum(exp_theta)
  
    def act(self, observation, reward, done):
        policy = self.get_policy()
        action = np.random.choice(self.num_products, p=policy)
    
        return {
            't': observation.context().time(),
            'u': observation.context().user(),
            'a': action,
            'ps': policy[action],
            'ps-a': policy
        }
  
    def train(self, observation, action, reward, done=False):
        if action is not None:
            self.trajectory.append({
                'action': action['a'],
                'reward': reward,
                'prob': action['ps']
            })
  
    def update(self):
        if len(self.trajectory) == 0:
            return
    
        # 计算累积回报
        rewards = [t['reward'] for t in self.trajectory]
        returns = []
        G = 0
        gamma = 0.99
        for r in reversed(rewards):
            G = r + gamma * G
            returns.insert(0, G)
        returns = np.array(returns)
    
        # 计算优势函数（使用baseline减少方差）
        if len(returns) > 1:
            baseline = np.mean(returns)
            advantages = returns - baseline
            std = np.std(advantages)
            if std > 1e-8:
                advantages = advantages / std
        else:
            advantages = returns
    
        # 策略梯度更新
        for t, adv in zip(self.trajectory, advantages):
            action = t['action']
            prob = t['prob']
            self.theta[action] += self.lr * adv * (1 - prob)
    
        self.trajectory = []
```

**理论对应：**

- 论文《Top-K Off-Policy Correction for a REINFORCE Recommender System》
- YouTube推荐系统中的REINFORCE应用
- 策略梯度方法的优势：直接优化目标策略

### 4.5 实验4：DQN Agent

**核心思想：** 学习Q(s,a)价值函数，使用经验回放稳定训练。

**Q-learning更新公式：**

$$
Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'} Q(s',a') - Q(s,a)]
$$

```python
class DQNAgent(Agent):
    def __init__(self, config, learning_rate=0.1, gamma=0.99):
        super(DQNAgent, self).__init__(config)
        self.lr = learning_rate
        self.gamma = gamma
        self.num_products = config.num_products
        self.Q = np.zeros(self.num_products)
        self.replay_buffer = []
        self.buffer_size = 2000
        self.epsilon = 0.3
  
    def act(self, observation, reward, done):
        if np.random.random() < self.epsilon:
            action = np.random.randint(self.num_products)
        else:
            action = np.argmax(self.Q)
    
        return {
            't': observation.context().time(),
            'u': observation.context().user(),
            'a': action,
            'ps': self.epsilon / self.num_products if np.random.random() < self.epsilon else 1 - self.epsilon + self.epsilon / self.num_products,
            'ps-a': np.zeros(self.num_products)
        }
  
    def train(self, observation, action, reward, done=False):
        if action is not None:
            self.replay_buffer.append({
                'action': action['a'],
                'reward': reward
            })
            if len(self.replay_buffer) > self.buffer_size:
                self.replay_buffer.pop(0)
  
    def update(self):
        if len(self.replay_buffer) < 32:
            return
    
        # 经验回放
        batch_size = min(64, len(self.replay_buffer))
        indices = np.random.choice(len(self.replay_buffer), batch_size, replace=False)
    
        for idx in indices:
            exp = self.replay_buffer[idx]
            action = exp['action']
            reward = exp['reward']
            self.Q[action] += self.lr * (reward - self.Q[action])
    
        # 探索率衰减
        self.epsilon = max(0.05, self.epsilon * 0.995)
```

**理论对应：**

- 论文《DRN: A Deep Reinforcement Learning Framework for News Recommendation》
- 价值函数方法的优势：样本效率高
- 经验回放：打破数据相关性，提高训练稳定性

## 五、训练与评估流程

### 5.1 离线训练函数

```python
def train_agent_offline(env, agent, num_users):
    """离线训练Agent"""
    unique_user_id = 0
    for _ in range(num_users):
        env.reset(unique_user_id)
        unique_user_id += 1
    
        # 获取初始观察
        observation, _, done, _ = env.step(None)
        agent.train(observation, None, None, True)
    
        # 使用环境内置策略生成数据
        while not done:
            old_observation = observation
            action, observation, reward, done, _ = env.step_offline(old_observation, 0, done)
            agent.train(old_observation, action, reward, False)
    
        # 处理最后一个动作
        action, observation, reward, done, _ = env.step_offline(observation, 0, done)
        agent.train(observation, action, reward, True)
```

### 5.2 在线评估函数

```python
def evaluate_agent_online(env, agent, num_users):
    """在线评估Agent"""
    unique_user_id = 1000
    total_clicks = 0
    total_steps = 0
  
    for _ in range(num_users):
        env.reset(unique_user_id)
        unique_user_id += 1
        agent.reset()
    
        observation, _, done, _ = env.step(None)
    
        while not done:
            # 使用Agent的策略进行推荐
            action = agent.act(observation, 0, done)
            observation, reward, done, _ = env.step(action['a'])
            agent.train(observation, action, reward, done)
        
            total_clicks += reward
            total_steps += 1
  
    return total_clicks / total_steps if total_steps > 0 else 0
```

### 6.2 结果分析

#### 6.2.1 简单方法的优势

Popularity Agent表现优异的原因：

- **数据稀疏性**：小规模实验中，复杂模型容易过拟合
- **群体智慧**：流行度反映了用户的整体偏好
- **稳定性**：不受探索策略影响，结果可复现

#### 6.2.2 探索策略的影响

ε-greedy实验结果：

- ε=0.0（纯利用）：CTR=0.0125
- ε=0.1（适度探索）：CTR=0.0139
- ε=0.2（较多探索）：CTR=0.0105
- ε=0.3（充分探索）：CTR=0.0156

**结论**：适当的探索能发现潜在优质物品，但探索过多会降低效果。

#### 6.2.3 强化学习方法的挑战

Policy Gradient和DQN表现不如简单方法的原因：

- **样本效率低**：需要大量数据才能收敛
- **稀疏奖励**：点击事件稀疏，学习信号弱
- **状态表示简单**：本实验未使用用户状态特征

### 8.2 新增Agent

#### 8.2.1 UCB Agent (Upper Confidence Bound)

**核心思想**：基于置信上界选择动作，平衡探索与利用。

**公式**：

$$
UCB(a) = Q(a) + c \cdot \sqrt{\frac{\ln N}{n(a)}}
$$

其中：

- $Q(a)$：物品a的平均奖励
- $N$：总选择次数
- $n(a)$：物品a被选择次数
- $c$：探索参数

**代码实现**：

```python
class UCBAgent(Agent):
    def __init__(self, config, c=2.0):
        super(UCBAgent, self).__init__(config)
        self.c = c
        self.Q = np.zeros(config.num_products)
        self.N = np.zeros(config.num_products)
        self.total_count = 0
  
    def act(self, observation, reward, done):
        if self.total_count < self.num_products:
            action = self.total_count  # 初始化阶段
        else:
            confidence = self.c * np.sqrt(np.log(self.total_count + 1) / (self.N + 1e-8))
            ucb_values = self.Q + confidence
            action = np.argmax(ucb_values)
        return {...}
```

**理论保证**：UCB是遗憾界最优的算法。

#### 8.2.2 Thompson Sampling Agent

**核心思想**：贝叶斯方法，对每个物品维护奖励概率的后验分布。

**原理**：

- 使用Beta分布作为共轭先验
- 观察到点击：$\alpha += 1$
- 观察到不点击：$\beta += 1$
- 从$Beta(\alpha, \beta)$采样，选择采样值最大的物品

**代码实现**：

```python
class ThompsonSamplingAgent(Agent):
    def __init__(self, config):
        super(ThompsonSamplingAgent, self).__init__(config)
        self.alpha = np.ones(config.num_products)  # Beta分布参数
        self.beta = np.ones(config.num_products)
  
    def act(self, observation, reward, done):
        samples = np.random.beta(self.alpha, self.beta)
        action = np.argmax(samples)
        return {...}
  
    def train(self, observation, action, reward, done=False):
        if action is not None:
            if reward > 0:
                self.alpha[action['a']] += 1
            else:
                self.beta[action['a']] += 1
```

**优势**：自然平衡探索与利用，效果通常优于UCB。

### 8.3 消融实验

消融实验用于分析各超参数对算法性能的影响。

1. **ε-greedy探索率**：最优ε值通常在0.1-0.3之间，过高会损害用户体验，过低则探索不足

## 九、V5进阶实操：算法增强与状态增强

### 9.1 实验目标

V5版本新增了一个进阶实验脚本 `reco-gym/my_entries/experiments_v5_advanced.py`，聚焦两个方向：

1. **算法增强**：在已有REINFORCE、DQN基础上，进一步实现 `Actor-Critic` 和 `PPO`
2. **状态增强**：在RecoGym原始观察较弱的前提下，显式构造更丰富的状态特征，包括：
   - 用户最近浏览序列
   - 上下文特征（时间、用户奇偶分桶、最近会话长度）
   - 正反馈历史（最近点击）
   - 负反馈历史（最近未点击/跳过）

### 9.2 状态增强设计

V5版本引入了 `StateFeatureBuilder`，提供两套状态表示用于消融实验：

| 状态版本           | 组成                                                           | 作用                         |
| ------------------ | -------------------------------------------------------------- | ---------------------------- |
| `Simple State`   | 最近浏览物品频次 + 会话长度                                    | 作为基础状态基线             |
| `Enhanced State` | 序列特征 + 正反馈历史 + 负反馈历史 + 上下文特征 + 最近反馈标记 | 模拟真实推荐中的用户状态建模 |

其中，增强状态的核心思想与论文中的两类做法相呼应：

- **YouTube REINFORCE / DeepPage**：强调用户序列与动态状态
- **DEERS**：强调正负反馈分离建模

### 9.3 新增Agent

#### 9.3.1 Linear Actor-Critic Agent

实现思路：

- `Actor`：使用线性参数化的Softmax策略，输出每个物品的选择概率
- `Critic`：使用线性状态价值函数估计 `V(s)`
- 更新方式：基于时序差分误差 `delta = r + gamma * V(s') - V(s)` 同时更新Actor和Critic

这样做的优点是：

- 比REINFORCE方差更低
- 不需要像DQN那样显式枚举复杂的Q值目标
- 适合在推荐系统中测试“策略 + 价值评估”的协同机制

#### 9.3.2 Linear PPO Agent

实现思路：

- 继续使用线性Softmax策略
- 收集轨迹中的 `state / action / old_prob / reward / value`
- 使用PPO的裁剪比率 `clip(ratio, 1-eps, 1+eps)` 控制策略更新步长
- 同时拟合一个线性Critic

这样做的目的不是完整复刻工业级PPO，而是验证：

- 推荐系统中的策略更新不宜过大
- 裁剪目标可以让训练过程更稳定
- 在弱监督、稀疏奖励场景下，PPO比朴素策略梯度更稳健

### 9.4 V5实验设计

V5包含两组实验：

**实验A：算法增强对比**

- `Popularity`
- `Actor-Critic`
- `PPO`

目标：观察在增强状态输入下，Actor-Critic和PPO是否能比静态基线更好地利用状态信息。

**实验B：状态增强消融**

- `AC-Simple` vs `AC-Enhanced`
- `PPO-Simple` vs `PPO-Enhanced`

目标：验证加入用户序列、上下文、正负反馈后，策略模型是否比只看简单浏览计数更有表达能力。

### 9.5 V5实验结果

在完成本机环境兼容修复后，`experiments_v5_advanced.py` 已经可以正常运行，并得到以下结果。

**实验A：算法增强对比**

| Agent        | CTR    | 结果解读                               |
| ------------ | ------ | -------------------------------------- |
| Popularity   | 0.0210 | 在当前RecoGym设定下仍然是强基线        |
| PPO          | 0.0117 | 略优于Actor-Critic，策略更新更稳定     |
| Actor-Critic | 0.0112 | 能学习状态信息，但整体仍弱于Popularity |

**实验B：状态增强消融**

| Agent        | CTR    | 结果解读                               |
| ------------ | ------ | -------------------------------------- |
| PPO-Enhanced | 0.0138 | 状态增强带来明显收益                   |
| AC-Simple    | 0.0117 | Actor-Critic在简单状态下更稳定         |
| PPO-Simple   | 0.0111 | 无增强状态时优势有限                   |
| AC-Enhanced  | 0.0105 | 当前线性Actor-Critic对增强特征利用不足 |

### 9.6 结果分析

V5实验有三个值得注意的现象。

**第一，RecoGym中的Popularity仍然很强。**
这与前几个版本的观察一致。RecoGym环境相对简化，用户特征和物品特征有限，因此统计型方法仍然可以取得较好的CTR。

**第二，PPO比朴素Actor-Critic更稳定。**
PPO通过裁剪策略更新幅度，避免策略在小样本条件下波动过大。在本次实验中，PPO在算法对比和状态增强消融中都表现出更好的稳定性。

**第三，状态增强对PPO有效，但对当前线性Actor-Critic未必立即带来收益。**
这说明“增加特征”本身并不自动等于“效果提升”，还取决于模型是否具备足够的表达能力去利用这些特征。至少在当前NumPy线性实现下，PPO对增强状态的适配性更好。

### 9.7 当前结论

从V5实验可以得到一个更细致的结论：

- 在简化环境中，**简单基线依然不可忽视**
- 在策略梯度类方法中，**PPO比朴素Actor-Critic更稳健**
- 在状态建模方面，**用户序列 + 上下文 + 正负反馈** 这样的增强状态是有价值的，但需要与合适的优化算法配合使用

这也进一步印证了强化学习推荐系统中的一个核心实践经验：算法改进和状态表示改进通常需要协同设计，单独增强其中一项未必能够稳定提升效果。
